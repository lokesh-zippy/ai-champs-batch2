Key Concepts

A faster first draft is not the goal. The question this module answers is whether AI-assisted engineering translates into production impact — shipped, accepted, quality output — and at what cost.

Productivity signal (necessary)

  • Code generated faster
  • Fewer keystrokes, less boilerplate
  • Quicker first draft of a test or PR description

Production impact (what counts)

  • Accepted, production-quality output delivered
  • Review and testing effort actually saved
  • Quality and regression signals holding or improving

The unit that matters is not cost per token or per request — it is total AI cost ÷ number of accepted, production-quality outputs.

The unit economics
cost per accepted output  =   total AI cost (tokens x model rate)
                              ---------------------------------------
                              # of outputs accepted at production quality

# A cheap-per-token run that needs five rework cycles and still
# ships flawed is EXPENSIVE on this measure.

This reframes a "cheap" model that produces rework as expensive, and a pricier model that lands correct output first time as cheap.

The ROI model and quality signals drive one of four governance actions for each AI workflow — and the decision is reported to leadership.

Measured vs Anecdotal Adoption

Why the ROI model and token economics exist as artifacts, not opinions.

✅ Measured

  • Before/after metrics justify the spend to leadership
  • Cost per accepted output guides model and context choices
  • Quality and regression signals sit alongside the savings
  • A workflow can be scaled, tuned, restricted, or retired on evidence

❌ Anecdotal

  • "It feels faster" — no number to defend or optimise
  • Token spend grows without anyone owning the trade-off
  • Rework and regressions are invisible in the productivity story
  • Workflows are never revisited once switched on

The Four Governance Actions

Given the ROI model and the quality signals, each AI workflow lands on one of these.

Scale when the before/after model shows clear saved effort, cost per accepted output is acceptable, and quality/regression signals hold. Roll it to more teams and more of the workflow.

Tune when the value is real but the cost per accepted output is too high — adjust the default model, tighten context discipline (Module 03), or set a per-workflow token budget, then re-measure.

Restrict when the workflow pays off only in narrow cases or carries a regression risk — limit it to those cases, or to reviewers who can catch its failure modes.

Retire when the ROI is marginal or negative, or quality signals degrade — turn it off and redirect the spend. Retiring a workflow is a valid, reportable outcome, not a failure.
