Key Concepts

The Model Context Protocol is an open standard that connects an AI agent to approved tools, repositories, services, and enterprise workflows through one consistent interface — instead of a custom, hand-built integration for every source.

The programme treats MCP as a key engineering capability for connecting agents to governed enterprise context. Retrieval-augmented generation (RAG) is intentionally excluded from the core programme so this time goes to deeper SDD, testing, and MCP work.

An MCP server wraps one system and advertises what an agent may do with it. The agent (the MCP host) discovers those capabilities at runtime and invokes them.

An MCP-connected agent can reach real systems, so the connection is only safe with deliberate controls around it.

The guiding rule: a curated, minimal set of tools with scoped permissions and human approval on consequential actions — if a human engineer can't say which tool a situation calls for, the agent can't be expected to either.

Once an agent-assisted workflow is proven, it is packaged as a reusable asset — not left as a prompt someone re-types.

MCP vs Custom Point-to-Point Integrations

Why a single protocol beats a bespoke connector per tool.

✅ MCP — one standard interface

  • One protocol for every approved tool, repo, and service
  • Capabilities discovered at runtime, not hard-coded
  • Permissions, approvals, and boundaries defined once
  • The same agent setup transfers across teams and projects

❌ Custom per-tool integrations

  • A bespoke integration to build and maintain for every source
  • Breaks whenever a tool's API changes
  • Governance bolted on per integration, inconsistently
  • Little of it transfers to the next project
