Key Concepts

The capstone is not a new topic — it is every capability from Modules 02–11 applied to one real use case, assembled into a single adoption plan.

For one software engineering use case, the team presents a complete package — each part with evidence, not just a description.

The use case determines the path — both were practised in Module 05, and both run on the same SDD foundation.

Greenfield SDD

  • A new feature or application
  • Spec → architecture & conventions → implement → test → release
  • Primary risk: under-specifying requirements

Brownfield enhancement

  • A change to an existing system
  • Repository archaeology → change-impact → minimal change → regression check
  • Primary risk: unintended regression

A Capstone That Lands vs a Demo That Doesn't

The rubric rewards evidence and realism over polish.

✅ Lands

  • Every claim backed by evidence — passing suite, judge output, traces
  • A real use case, greenfield or brownfield, chosen deliberately
  • An ROI model built on measured before/after numbers
  • A phased roadmap with named metrics and expansion criteria

❌ Doesn't

  • "It works" with no test evidence or monitoring design
  • A toy example that avoids the hard parts of the codebase
  • ROI asserted as a percentage with no baseline
  • "Roll it out to everyone" with no phasing or measures

The Roadmap, Phase by Phase

What actually happens in each 30-day window.

One team, one workflow, one use case. Put the reusable skill/spec pack and the Copilot customization layer in place, baseline implementation cycle time, PR review time, testing effort, and token spend, and stand up Agent Prism monitoring.

Run the workflow for real and measure against the baseline — cycle time, PR review time, regression/defect signals, reusable skill/spec adoption, token spend discipline, and early ROI signals from the post-training assessment framework.

Where the evidence holds, roll to more teams; apply Module 11's scale / tune / restrict / retire decision per workflow; report the business case and governance controls to leadership as the enterprise rollout plan.
